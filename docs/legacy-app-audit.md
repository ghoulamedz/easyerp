# Legacy application audit — the defects easyERP must not reproduce

A static review of RayhanERP, the application easyERP replaces. No test was ever run against it and none could be: there is no suite. Findings marked _likely_ were read off the source, not reproduced.

**This document exists to answer one question when designing a module: which defect from the app we are replacing is this module at risk of reproducing?** A feature that reopens an old defect is not a new feature, it is a regression with better typography.

Each finding below names where easyERP's answer lives, or says plainly that the answer is not built yet. The last column is the point of the table: most of section 2 is still unbuilt, so those modules have no protection yet.

## 3. What the legacy app had no concept of

These are not bugs in it; they are gaps, and each is a thing easyERP promises that a reader should hold us to.

- **No invoicing at all.** No invoice entity, no fiscal document, no numbering to a tax authority. PDFs were assembled in the browser, and one template numbered every quote `DEV-001`.
- **No payment recording** and no allocation of a payment to an invoice.
- **No change tracking.** No history of who did what, so every investigation was a guess.
- **No audit trail**, so a record could not be shown to have been altered — or not.
- **Pagination and DTOs missing**: controllers returned entities and collections directly, which is how the hash exposure and the totaux mismatch both became reachable.

## 4. How to use this file

When designing a module, read the row that matches it. If the **Status** column says _Not built_, that module has no protection yet and the defect above is live in easyERP until it is. That is the honest state of the project today: the design decisions exist as ADRs and contracts, and the enforcement is mostly still to be written.
